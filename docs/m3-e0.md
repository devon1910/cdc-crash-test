# M3: load generator and E0 baseline

E0 writes committed rows to `public.orders` while Debezium is running. The observer records slot and WAL metrics at the same time. This establishes a working baseline before testing quiet or stopped CDC in later milestones.

Run from the repository root after `docker compose up -d`:

```text
make e0
```

If GNU Make is unavailable on Windows, the equivalent is:

```text
go run ./cmd/e0
```

The default run writes ten `orders` rows per second for ten minutes, samples every five seconds, waits five seconds for the last changes to be acknowledged, and writes `results/e0/<UTC timestamp>/observations.csv` and `summary.md`. A shorter trial is `go run ./cmd/e0 -duration=1m`. The standalone load generator accepts `-orders`, `-noise`, `-rate`, `-noise-bytes`, and `-duration`, for example `go run ./cmd/load -orders -rate=10 -duration=1m`.

E0 waits up to 60 seconds for an active slot and `UP` Debezium health before starting. Its proposed acceptance rule is in [ADR-004](adr/004-e0-baseline-verdict.md): the confirmed flush LSN advances, every sample reports an active slot and `UP` health, peak retained-WAL LSN distance is at or below one WAL segment, and no gap between samples exceeds two sampling intervals plus two seconds. The summary gives the actual start/end/min/max values, net growth rate, largest gap, versions, and verdict. A failed rule exits nonzero and points to the summary. The rule is a local lab heuristic; read the CSV and summary before drawing conclusions about other workloads.

For the meaning of LSN, WAL, slot, and checkpoint, see [CDC terms](cdc-terms.md).
